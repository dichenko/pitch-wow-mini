# Proposal: Create Reusable AI Assistant Deployment Template

## Change ID

```text
create-ai-assistant-template
```

## Summary

Create a reusable template for fast deployment of Telegram AI-assistants based on the existing `dichenko/uz-stomatolog` project patterns.

The template SHALL include:

- Telegram bot service with LangChain agent and multiple tools.
- Default `send_to_admin` tool that forwards information to the admin chat with automatic user data enrichment and DB fallback.
- Optional censor / response reviewer LLM pass with versioned censor prompt and admin UI toggle.
- Optional voice recognition pipeline with OpenAI STT (primary) and Aisha STT (fallback for Uzbek).
- Separate admin web service for prompt/tool-instruction/censor management.
- PostgreSQL database with Alembic migrations.
- Docker Compose without Caddy inside containers.
- External host-level Caddy reverse proxy.
- Configurable host ports for multi-project deployment on a single VPS.
- Admin access through Telegram `/admin` one-time temporary login links.
- Role-based admin management (read / write / superadmin).
- Versioned editable system prompt with restore capability.
- Versioned editable tools instruction with restore capability.
- Audit log for all admin actions.
- LangSmith observability integration for tracing agent runs, LLM calls and tool calls.

## Why

Every new AI-assistant currently requires manual assembly: bot, database, prompts, admin panel, access control, Caddy configuration, ports, deployment.

A reusable template eliminates repeated infrastructure work and lets developers launch new assistants in 10–20 minutes after filling `.env`.

## Non-goals

- Do NOT build a visual tool constructor.
- Do NOT allow admins to execute arbitrary code from the web UI.
- Do NOT build multi-tenant SaaS within a single application instance.
- Do NOT store secrets in the database.
- Do NOT include Caddy inside Docker Compose.
- Do NOT build a complex CRM.
- Do NOT build a billing system.

## Main Architectural Decision

Caddy runs once globally on the host server.

Each project raises only its own containers:

- `bot`
- `admin`
- `postgres`

Containers bind ports only to `127.0.0.1`.

Caddy reverse-proxies public domains to local ports of the specific project.

## Risks

| Risk | Mitigation |
|------|------------|
| Port conflicts when running multiple projects on one VPS | Use configurable host ports generated by init script |
| Admin login token exposure | Store only SHA-256 hash, single-use, short TTL |
| Admin accidentally breaks agent behavior by editing prompt | Non-editable core guardrails prepended to all prompts; version history with restore |
| Restore overwrites current version losing history | Restore creates a NEW version copied from selected old version |
| Root admin lost from DB | `ROOT_ADMIN_TG_ID` from `.env` always grants superadmin regardless of DB state |
| LangSmith API unavailable breaks conversations | Best-effort integration; failures logged locally, conversations continue |
| Censor LLM failure blocks user response | Best-effort censor: on failure, send draft response as-is; log error to debug page |
| Voice STT both providers fail | User-friendly fallback message asking to send text; STT errors logged but not exposed |
| ADMIN_TELEGRAM_CHAT_ID not configured | send_to_admin saves to DB and does not break conversation |

## Success Criteria

- A new project can be raised on a VPS in 10–20 minutes after filling `.env`.
- `/admin` command sends a one-time login link to the admin.
- The link expires and cannot be reused.
- Root admin from `.env` always has superadmin access.
- Superadmin can add/remove other admins.
- Read admin cannot edit anything.
- Write admin can edit prompts/tools instruction but cannot manage admins.
- Superadmin can manage admins.
- All prompt/tools instruction changes are saved as new versions.
- One of the last three versions can be restored.
- LangChain agent receives the active system prompt + active tools instruction on every request.
- Tool calls are logged locally and visible in LangSmith when tracing is enabled.
- The `send_to_admin` tool is available out of the box in every assistant created from the template.
- `send_to_admin` works even without `ADMIN_TELEGRAM_CHAT_ID` (saves to DB).
- Censor can be enabled/disabled from admin UI; censor prompt is versioned.
- Censor failure does not block user response (draft is sent as fallback).
- Voice messages are transcribed via OpenAI STT with Aisha fallback.
- Voice recognition can be disabled via `VOICE_ENABLED=false`.
- LangSmith tracing is optional; bot works without API key when disabled.
- Secrets never appear in LangSmith metadata, tags, inputs or outputs.

## Scope

This change creates the full template structure including:

- Repository layout (apps/bot, apps/admin, packages/shared, infra, scripts, openspec).
- Docker Compose configuration.
- Database schema and migrations.
- Admin authentication flow.
- Prompt versioning system.
- LangChain agent with template tools including a default `send_to_admin` tool.
- Optional censor / response reviewer with versioned censor prompt.
- Optional voice recognition pipeline (OpenAI STT + Aisha fallback).
- LangSmith observability integration.
- Init script for environment setup.
- Deployment documentation.
